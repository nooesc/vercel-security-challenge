## SBX-013 proof hardening

The initial harness used one value for request correlation and credential injection, which could not prove retrieval of a value unknown to the guest. The harness now creates separate correlation and brokered canaries; only the correlation value enters the guest configuration.

Three fresh separated-secret harness runs reproduced the encoded dot-segment signal. An initial standalone PoC proved synthetic credential recovery through a controlled reflecting endpoint. Because that result depended on reflection, the final PoC replaced it with an authenticated outside action and added:

- a matched-path positive control;
- a canonical outside negative control;
- an explicit `/outside` action that returns `401` without the registered credential;
- an opaque operation ID rather than credential reflection;
- controller/observer SHA-256 comparison of the synthetic credential;
- a guard proving the brokered secret is absent from guest configuration.

Authenticated-action runs `639e6a5a-d7e3-45f7-ba90-2f2e28ede5ac` and `a1ef4cb0-eb8b-46ea-9178-8609953f7b50` passed both controls. In each run, canonical `/outside` returned `401`, while `/matched/%2e%2e/outside` routed to the same handler with the injected credential and authorized exactly one action. The guest response contained no credential. Both sandboxes stopped and deleted successfully. See the draft finding and redacted evidence under `findings/` and `pocs/SBX-013/`.
