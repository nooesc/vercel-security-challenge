# SBX-038: HTTP/1 CONNECT authority confusion

## Hypothesis

With a policy that has exactly one transformed origin A, the Sandbox firewall terminates and parses outer TLS for A. A hostile HTTP/1 client then sends an intentionally inconsistent but bounded request:

```http
CONNECT b.research.test:443 HTTP/1.1
Host: a.research.test
```

The candidate root cause is an authority-source mismatch: authorization and credential transformation use outer TLS SNI / `Host` A, while a generic CONNECT path dials authority-form B. If that happens, the guest can establish a second, certificate-verified TLS session to denied B inside the tunnel.

This is distinct from SBX-008/009/010 (ordinary and absolute-form requests / connection reuse), SBX-034/037 (`forwardURL` routing), and SBX-036 (Postgres pre-TLS parsing). RFC 9112 defines authority-form as the fourth HTTP/1 request-target form and reserves it for CONNECT.

The direct product contradiction is Vercel's statement that traffic outside the allowlist is denied and an unauthorized destination is rejected before any data is transmitted. Vercel documents proxy routing as an explicit `forwardURL` rule; this policy has only an A transform and no `forwardURL`.

## Evidence bar

The public stage runs five fresh, one-connection/no-retry cases at no more than two cases per second:

1. Direct ordinary HTTPS to B is actively blocked.
2. Normal A succeeds and receives exactly one controller-only transformed canary.
3. `CONNECT A:443` reaches the owned A terminal, which returns `405` and never dials anywhere.
4. `CONNECT B:443` with outer TCP/TLS/SNI/Host A attempts one nested, certificate-verified TLS request to B.
5. Direct ordinary HTTPS to B remains blocked.

Active and independent views must show the same session and exact A transform policy before and after the cases. A public candidate requires a B-only nested action and zero A CONNECT event for the attack case. Reachability alone is assessed as Medium.

Only after the public sandbox has been stopped, deleted, and found absent three times does the controller create a fresh sandbox. It writes one new synthetic value to a mode-`0600` file and repeats the full controls. High requires B to receive the exact value, match a keyed HMAC commitment, and return only an opaque operation ID. The receiver does not retain the body, a plain digest, command output, or raw credential.

## Owned infrastructure prerequisite

A Quick Tunnel or Worker is not assumed to preserve HTTP CONNECT. The controller first sends CONNECT from outside Sandbox and requires the `x-sbx038-terminal: 1` response generated by this receiver. If a CDN rejects or consumes CONNECT first, the run stops before creating a sandbox.

The currently coordinated single-run arrangement is:

- A is `https://a-sbx038.form-app.app`. Its DNS-only A record points to the operator-owned public address `75.178.152.106`. On `cyrus-mm`, the receiver listens with the valid public A certificate on `0.0.0.0:43138`; the owned ASUS router maps external TCP/443 byte-for-byte to `192.168.50.69:43138`. No CDN, Worker, or HTTP reverse proxy may consume A's CONNECT request.
- B is a distinct owned HTTPS name. The B receiver binds only `127.0.0.1:43139`; a controller-side SSH `-L` carries that loopback port, and a separately owned local `cloudflared` process exposes B. Set `SBX038_B_TRANSPORT_MODE=public-edge` for this topology. The B path must satisfy the controller's exact TLS/SNI/certificate health preflight before receiver configuration or sandbox creation. A generic tunnel response is never evidence.
- The controller talks to the admin API through A with the fresh bearer key. The guest never receives the key, transform value, file value, tunnel command, certificate path, or Vercel token.

After the bounded controller finishes, remove the receiver, local tunnel, SSH forward, router rule, temporary DNS record, certificate material, and any deployment used only for this run. The controller's own journal/lock is released only after both sandboxes and the receiver run have exact delayed absence proof; infrastructure teardown comes afterward.

## Receiver

Generate the admin key locally and do not paste or commit it. Start B's Quick Tunnel first if using one, then set its URL below. The A example assumes public TCP/443 is mapped directly to the process's A listener and the process is permitted to bind that port.

```sh

export SBX038_A_PUBLIC_ORIGIN='https://a.example-owned.test'

export SBX038_A_TLS_KEY_PATH='/absolute/path/to/a.key.pem'
export SBX038_A_TLS_CERT_PATH='/absolute/path/to/a.fullchain.pem'
```

Wait for `{"ready":true,...}` and verify both public `/healthz` endpoints. Reuse the same `SBX038_ADMIN_KEY` only in the controller process.
For a direct receiver-local B deployment instead of the coordinated tunnel edge, also set `SBX038_B_TLS_KEY_PATH` and `SBX038_B_TLS_CERT_PATH` and use `SBX038_B_TRANSPORT_MODE=receiver-local`; the verdict rejects either mode if its receiver event reports the other termination shape.
